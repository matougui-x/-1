# 校园失物招领

一个纯前端的校园失物招领信息平台，实现「**发布信息 → 浏览/搜索 → 查看详情 → 联系发布者 → 更新状态**」这条完整主线。

这是《软件工程》第二次结对作业的代码实现，基于第一次结对作业的原型设计（手机端 375×812，主色 `#12A87A`，卡片圆角 14px），在同一套设计规范上扩展出了桌面端形态。

---

## 一、快速开始（三种方式任选）

### 方式 1：直接打开（推荐，零依赖）

下载全部文件后，**用谷歌浏览器打开根目录下的 `index.html`** 即可：

```
双击 index.html
  或
右键 index.html → 打开方式 → Google Chrome
```

不需要安装 Node.js，不需要起本地服务器，不需要联网。第一次打开会自动灌入一批演示数据，可以直接点击体验全部功能。

> 请使用 **谷歌浏览器（Chrome）**。其它浏览器也能运行，但 `file://` 协议下不同浏览器对本地存储的处理有差异（Firefox 会把每个本地文件当成独立来源，导致页面之间读不到彼此的数据），Chrome 是本次统一指定的测试环境。

### 方式 2：运行单元测试

**双击 `test/test.html`**，用 Chrome 打开，会自动跑完全部 159 个测试用例并显示绿色/红色报告。

### 方式 3：起一个本地服务器（可选）

如果你更习惯用 `http://` 访问，在项目根目录执行：

```bash
python -m http.server 8080        # Python 3
# 或
npx serve .                       # 需要 Node.js
```

然后访问 <http://localhost:8080/index.html>。

## 三、功能一览

| 功能 | 在哪里 | 说明 |
| --- | --- | --- |
| 发布寻物 / 招领信息 | `publish.html` | 顶部切换类型，共用一套表单，字段级校验 |
| 集中浏览 | `index.html` | 卡片列表，标出寻物/招领与当前状态 |
| 关键词搜索 | `search.html` | 命中物品名、描述、地点、分类；多关键词按「与」匹配；忽略全角/大小写 |
| 分类 / 地点 / 状态筛选 | `index.html` | 桌面用左侧栏，手机用图标条与下拉 |
| 查看详情 | `detail.html` | 完整信息 + 发布者联系方式 + 安全提示 |
| **更新状态** | `mine.html` / `detail.html` | 发布者标记「已找到」或「已归还」，别人就不会再白跑 |
| 我的发布 | `mine.html` | 按进行中/已完成分组，可编辑、删除、撤回状态 |
| **认领验证（防冒领）** | `publish.html` → `verify.html` | 招领信息可隐藏 2–3 项关键特征，认领人答对才看到联系方式 |
| 一键复制联系方式 | 详情页 / 验证通过页 | 复制失败时自动弹出可手动复制的输入框 |
| 搜索历史与热门搜索 | `search.html` | 最近 10 条，可单条删除或一键清空；热词由真实数据统计 |

### 关于「认领验证」

这是本项目最有价值的一个设计，解决的是**冒领**问题：招领信息如果把联系方式直接公开，任何人都能看到，真正的主人反而可能被抢先。

做法是：发布招领信息时，系统按物品分类给出预设问题（证件卡片问「卡面姓名 / 卡号后四位 / 卡面标记」，雨伞问「伞面颜色 / 伞柄特征」……），发布者只填答案。认领时随机抽 2 项作答，全部答对才解锁联系方式并生成认领凭证码；答错扣次数，3 次用完转为「申请人工核对」。

**答案在任何对外数据里都不存在**——列表、搜索结果、详情页拿到的对象已经被数据层剥掉了答案字段（见 `js/store.js` 的 `toPublic`），不是靠前端隐藏。这条规则有单元测试直接验证。

## 四、开发与测试

### 运行单元测试

双击 `test/test.html`（Chrome 打开）即可，离线可用。

测试覆盖的是**业务逻辑**，不依赖 DOM：`js/store.js` 采用「纯逻辑 + 注入式存储适配器」的设计——浏览器里注入 `localStorage`，测试里注入内存实现。因此测试不需要 jsdom，不需要起服务器，也不需要装 Node.js。

### 自检标记

每个页面渲染完成后会在 `<html>` 上写一个 `data-selftest` 属性，例如：

```html
<html data-selftest="PASS|page=home|cards=14">
```

开发时可以用命令行批量检查所有页面是否正常运行：

```bash
chrome --headless --disable-gpu --dump-dom "file:///路径/index.html"
```

失败时会变成 `FAIL:...`。这一点有必要单独说明：**浏览器里 JS 抛异常时进程退出码仍然是 0**，只看退出码判断不出页面有没有跑起来。

### 第三方库

`test/lib/` 下的 Mocha 与 Chai 是从 npm 官方源下载后**随仓库一起提交**的浏览器版构建：

| 库 | 版本 | 为什么选这个版本 |
| --- | --- | --- |
| Mocha | 12.0.3 | 提供 `mocha.js` / `mocha.css` 浏览器构建，`<script>` 直接加载 |
| Chai | 4.5.0 | 5.x 起只提供 ES Module，而 `file://` 下 `type="module"` 会被 CORS 拦截 |

需要重新获取时执行 `python test/lib/_fetch-libs.py`。

## 五、技术选型说明

| 决定 | 原因 |
| --- | --- |
| 不用 ES Module，用经典 `<script>` 标签 | `file://` 协议下 `type="module"` 会因跨源限制加载失败。所有模块挂在 `window.LF` 命名空间下，按依赖顺序加载 |
| 不用任何前端框架 | 作业要求「下载后双击就能用」，引入框架必然带来构建步骤或网络依赖 |
| 数据存 localStorage | 无后端。写入前先检测存储是否可用（无痕模式、企业策略下会抛 SecurityError），依次降级到 sessionStorage、内存，并在页面顶部提示用户 |
| 照片压缩后再存 | localStorage 只有约 5MB，原图转 base64 会很快写满。统一缩到最长边 900px 并逐级降低质量，直到单张不超过 6 万字符 |
| 存储软上限 200 万字符 | 提前拦住写入，给出「去我的发布删除旧信息」这种能照做的提示，而不是等浏览器抛异常 |
| 种子数据写在 `js/seed.js` 里 | `file://` 下 `fetch()` 必然失败，演示数据不能放在 JSON 文件里靠请求加载 |

## 六、已知限制

- 没有账号体系（作业不要求实名认证），用本机生成的随机 id 判断「我的发布」。因此换浏览器、换电脑、清除浏览器数据都会看不到自己发布过的内容。
- 数据只存在本机，不同用户之间不共享——这是无后端方案的固有边界。
- 认领尝试次数记录在信息上，而不是按认领人区分。在真实的多人环境下应按用户计数，本项目作为课程作业做了简化。
- 繁简中文不互通（搜「校園卡」找不到「校园卡」）。做个简繁转换表能用十几行解决，但会引入一份无法测试覆盖的映射数据，性价比不高，故不做。
