> 这份文档用于博客的「目录说明」与「使用说明」两个评分点，内容与仓库根目录的 `README.md` 一致，可以按需复制。

## 一、目录是怎么组织的

整个项目按「**页面 → 样式 → 逻辑 → 测试 → 文档**」五层分开，每一层再按职责往下分。核心思路是：**页面文件只管结构，业务规则全部收在数据层**，这样业务逻辑才能被单元测试完整覆盖。

```
校园失物招领Web/
│
├── ① 页面层：8 个 HTML，一个页面一个文件，文件名即用途
│   ├── index.html          首页：浏览 + 筛选 + 排序
│   ├── search.html         搜索：关键词、搜索历史、热门搜索
│   ├── detail.html         详情：完整信息 + 联系方式 + 状态维护
│   ├── publish.html        发布/编辑：寻物与招领共用一套表单
│   ├── success.html        结果：公开展示内容预览
│   ├── mine.html           我的发布：状态维护、编辑、删除、认领申请、数据管理
│   ├── verify.html         认领验证：回答隐藏特征
│   └── verify-result.html  认领结果：通过与未通过两种形态
│
├── ② 样式层：3 个 CSS，从抽象到具体
│   ├── css/tokens.css      设计令牌（颜色、圆角、阴影、字号）+ 基础重置
│   ├── css/components.css  通用组件（卡片、标签、按钮、表单、弹层、空状态）
│   └── css/layout.css      响应式布局（900px 断点，桌面 ⇄ 手机）
│
├── ③ 逻辑层：先分「通用 / 数据 / 界面」，再按页面拆控制器
│   ├── js/error-hook.js    页面自检钩子
│   ├── js/config.js        业务字典：类型、分类、地点、状态、隐藏特征预设问题
│   ├── js/utils.js         纯函数工具：时间、文本归一化、图片压缩、剪贴板
│   ├── js/store.js     ★   数据层：全部业务规则，本项目最重要的文件
│   ├── js/seed.js          演示数据
│   ├── js/ui.js            界面公共层：导航外壳、卡片渲染、轻提示、弹窗
│   └── js/page-*.js        8 个页面的控制器，与 HTML 一一对应
│
├── ④ 测试层：入口 + 用例 + 本地内置的第三方库
│   ├── test/test.html      测试入口，双击即跑
│   ├── test/specs/*.spec.js 用例，按被测模块分文件
│   └── test/lib/           Mocha 与 Chai 的浏览器构建（随仓库提交，离线可用）
│
└── ⑤ 文档层
    └── docs/*.md           目录说明、PSP、博客草稿
```

### 命名约定

- **页面**：`动词/名词.html`，小写，多词用连字符（`verify-result.html`）。
- **样式**：`tokens / components / layout`，分别回答「长什么样 / 有哪些零件 / 怎么摆」。
- **脚本**：`page-xxx.js` 一定是某个 HTML 的控制器，与页面同名，一眼能对上；不带 `page-` 前缀的是被复用的公共模块。
- **数据字段**：一律小驼峰，语义直白（`happenedAt`、`contactWay`、`doneType`），字典类字段用 `key` 而不是中文，中文只出现在 `config.js` 里。

### 为什么把业务逻辑单独抽到 `store.js`

因为它决定了这个项目**能不能被测试**。

`js/store.js` 用「纯逻辑 + 注入式存储适配器」的写法：`createStore(storage)` 只要求传入的对象提供 `getItem / setItem / removeItem` 三个方法，和 `localStorage` 的接口完全一致。于是：

```js
// 浏览器里
LF.createStore(window.localStorage)

// 单元测试里
LF.createStore(LF.createMemoryAdapter())   // 内存实现，每个用例互不干扰
```

业务代码一个字都不用改。所以 159 个测试用例全部是纯函数测试，**不需要 jsdom、不需要起服务器、不需要装 Node.js**，双击 `test/test.html` 就能跑。

### 数据流

```
用户在页面上操作
      ↓
page-*.js 收集表单/筛选条件，调用 store 的方法
      ↓
store.js 校验 → 处理业务规则 → 通过适配器读写存储
      ↓
返回「公开视图」对象（toPublic 已剥掉隐藏特征答案）
      ↓
page-*.js 交给 ui.js 渲染成卡片/表单/提示
```

关键点：**页面永远拿不到隐藏特征的答案**。答案只在 `store.submitClaim()` 内部参与比对，比对完也不返回。详情页、列表页、搜索页的数据全部经过 `toPublic()` 过滤。

## 二、测试人员如何运行

### 运行程序

1. 把整个 `校园失物招领Web` 文件夹下载到本地；
2. **用谷歌浏览器打开根目录下的 `index.html`**（双击，或右键 → 打开方式 → Google Chrome）。

不需要安装任何东西，不需要起服务器，不需要联网。

> **请使用 Chrome。** 其它浏览器也能跑，但 `file://` 协议下不同浏览器对本地存储的处理不一样：Chrome 把所有本地文件视为同一来源，页面之间能共享数据；Firefox 会把每个文件当成独立来源，导致「发布成功后跳到成功页，数据却读不到」。本次作业统一指定 Chrome。

3. 第一次打开会自动灌入一批演示数据（14 条信息，其中 2 条归属于你，方便演示「我的发布」），页面右上角会提示「已为你准备了一批演示信息」。

### 运行单元测试

**双击 `test/test.html`**，用 Chrome 打开，会自动跑完全部 159 个用例并显示报告：

- 绿色 ✓ 表示通过，红色 ✗ 会同时打印期望值与实际值
- 右上角统计里的 `passes / failures` 就是通过和失败的数量
- 全部通过时页面不会出现任何红色内容

### 建议的验收走查路线

按下面这条路线走一遍，就能覆盖作业要求的全部核心功能：

| 步骤 | 操作 | 应该看到 |
| --- | --- | --- |
| 1 | 打开首页，点几个分类图标、切换「寻物/招领」 | 列表随之筛选，标题和条数同步变化 |
| 2 | 顶部搜索框 → 输入「校园卡」 | 出现搜索结果，条数正确；搜不到时给出空状态和下一步建议 |
| 3 | 点任意一张卡片进详情 | 看到完整信息、地点、发布人（姓名打码） |
| 4 | 打开一条**带 🔒 需验证**的招领信息 | 联系方式显示「通过认领验证后可见」，看不到答案 |
| 5 | 点「我要认领（需验证）」，**先故意填错** | 跳到「验证未通过」，列出错题、剩余次数减 1 |
| 6 | 再答一次，这次填对 | 跳到「验证通过」，给出凭证码和解锁后的联系方式，可一键复制 |
| 7 | 点顶部「＋ 发布信息」，发一条招领信息 | 填写时能实时看到「已填写 N 项隐藏特征」的提示；缺少必填项时字段标红并给出原因 |
| 8 | 发布成功 → 「查看我的发布」 | 新信息出现在「进行中」里 |
| 9 | 点「标记已归还」并确认 | 该条目移到「已完成」；回首页能看到它变成「已归还」 |
| 10 | 在「我的发布」里点「认领申请」 | 弹出收到的认领记录，含通过/未通过和对方填的答案 |

**想知道隐藏特征的正确答案时**：`seed_mine_1`（校园卡）的答案是「卡面姓名=王小明、卡号后四位=3882、卡面标记=蓝色小熊贴纸」，可以用它来验证「答对通过」这条路径。

### 演示前想恢复初始状态

在「我的发布」页底部有「本地数据」区域，点「恢复演示数据」即可清空自己发布的内容并重新灌入演示数据。旁边还有「导出数据」，可以把全部数据（含隐藏特征答案）复制出来备份。

## 三、常见问题

**Q：打开页面是空白的？**
A：确认是用 Chrome 打开的、并且 `css/` 和 `js/` 目录与 HTML 在同一个文件夹里（不要只复制单个 HTML 文件）。

**Q：发布的信息刷新后没了？**
A：多半是用了无痕模式，或浏览器设置里禁用了本地存储。这种情况下页面顶部会出现一条黄色提示条说明原因。程序会自动降级到会话存储，并明确告知数据保留范围。

**Q：换台电脑打开，自己发布的信息不见了？**
A：这是预期行为。本项目没有后端，数据保存在本机浏览器里。不同机器、不同浏览器之间不共享数据。

**Q：搜索结果里有些字搜不到？**
A：搜索按归一化后的文本做子串匹配，全角/半角、大小写、多余空格都不影响。但繁简中文不互通——搜「校園卡」找不到「校园卡」，这一点在 README 的「已知限制」里也写了。
