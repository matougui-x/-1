## 这个 PR 做了什么

两个改动，其实是同一个设计意图的两半：**把"公开信息面"这件事对用户讲清楚，并且让每一种分类都有一套说得通的流程。**

1. **搜索引导**：分类的公开特征被锁成固定 1–2 项之后，失主搜不到东西会误以为"没人捡到"。现在首页选中分类时，直接告诉他"这一类只公开哪几项、请按它们搜、哪些内容搜不到"。
2. **「其他」类走信任原则**：这一类没有可锁的客观特征，**不再要求出验证题**——描述和照片直接公开、联系方式直接可见，见到的人直接联系发布者核对。

## 1. 搜索引导

**问题**：公开面收窄后，一条信息能命中的只有标题、地点和那一两个特征。失主仍按习惯搜「蓝色充电宝」，搜出 0 条——而 **"0 条结果"和"没人捡到"在页面上长得一模一样**，他会直接放弃。

**做法**：分类字典加 `searchHint`（`js/config.js` 的 `LF.CATEGORIES`），首页选中分类时显示在筛选区旁（手机端在筛选条下），文案由 `LF.searchHintFor()` 统一给出：

| 分类 | 页面上的引导语 |
| --- | --- |
| 证件卡片 | 🔍 本类只公开卡号：请按证件号搜索（记不全的位用 `*` 顶位，位数要和卡号一样长），姓名、院系、卡号之外的细节都不公开。（卡号（打码））（就是全部可搜的公开特征） |
| 电子产品 | 🔍 本类只公开品牌和型号：请按品牌或型号搜索，颜色、外观、保护壳都不在公开信息里。（品牌、型号）（就是全部可搜的公开特征） |
| 其他 | 🔍 这一类不好指定公开特征，也不出认领验证题：描述和照片直接公开，请翻列表（或用描述里的词、按地点）找，翻到了直接联系发布者核对。 |

三个要点：

- **不只说"请搜 X"，还说清"搜不到什么"**——否则失主不知道"颜色"根本不在公开面里，照样会去搜。
- **显不显示只由字典决定**（写了就显示、没写就返回空串），页面不维护第二份分类名单。未知分类不显示，也不会凭空编一句默认文案。
- **文案自带兜底**：`searchHintFor()` 检查 `searchHint` 里有没有提到字典里的字段名，没提到就把字段名附上——改了特征名忘了改文案时当场自曝，而不是让失主照着过时提示搜。

原有特征筛选按钮**全部保留**：引导管"关键词怎么搜"，筛选按钮管"点一下筛"，两者互补。

## 2. 「其他」类：对照组，不出验证题

**问题**：「其他」之所以是「其他」，正因为它没有客观、能锁死的细节（一本书、一串钥匙）。硬要出题，出题人只能把描述里的细节再抄一遍，还可能被冒领者照着公开描述选对——**在一类没有可锁特征的信息上强制出题，只会逼人编题。**

**做法**：这一类改走**信任原则**——不出题，描述 + 照片直接公开，联系方式直接可见。判断收在一个函数里：

| 分类 | `LF.allowVerifyFor()` | 出题 | 谁看得到联系方式 |
| --- | --- | --- | --- |
| 有公开特征的八类 | `true` | 必须出 3–5 题 | 答对全部题目的人 |
| 其他 | `false` | **不出题** | 所有人（公开） |
| 字典里没有的分类（脏数据） | `null` | 不校验 | 分类字段自己已报错，不再叠加 |

四个实现上的决定：

1. **判断依据是"分类有没有公开特征"，不是手写 `category === 'other'`**——将来出现第二个"不出题"的分类，只改 `store.js` 一处。返回**三态**是为了脏数据：分类不在字典里时"该不该出题"无从判断，返回 `null` 让校验跳过，免得在"分类错误"上再叠一条用户改不掉的报错。
2. **数据层说了才算**：`store.create` / `store.update` 对「其他」强制把 `questions` 置空（和"描述按分类置空"同一套路），前端传了题目也落不了盘；`needsVerify()` 恒为 false，`startClaim()` 明确回"这条信息不需要验证"。
3. **旧数据就地清掉（`DATA_VERSION` 3 → 4）**：演示数据 `seed_6` 原本挂着 4 道题，v3 的真实数据也可能有。只改新流程的话，这些老记录会继续要求答题，而发布页**已经没有题目编辑入口**——发布者连"删掉这套题"都做不到，会被永久锁在旧流程里。迁移把题目清空并复位作答次数。
4. **页面给"去处"，不是把出题区一藏了事**：选中「其他」时出题区换成一整块说明（为什么不出题、描述会直接公开、**代价**是没有防冒领闸门），切换分类时两者自动互斥；详情页、我的发布、发布成功页各说一句，免得认领人以为页面坏了、发布者以为自己漏填了。

**已知代价（已写进 README「已知限制」）**：这一类没有防冒领闸门，谁先看到都能联系发布者。换来的是这个分类终于有说得通的流程。

**逻辑层**

- `js/config.js` — `DATA_VERSION` 3 → 4、`LF.CATEGORIES` 加 `searchHint`（含「其他」）、新增 `LF.featureNamesFor()` / `LF.searchHintFor()` / `LF.SEARCH_HINT_SUFFIX`
- `js/page-publish.js` — 新增 `categoryAllowsVerify()` / `applyVerifySection()`，出题区改由"类型 + 分类"共同决定

**测试**（`test/specs/`，全套 **262 个用例，全绿**）

- `verify.spec.js` — 「其他」类不开放认领入口
- 另有一处**既有断言按新行为调整**：`validatePost` 在"分类非法"时不再叠加 `questions` 报错（原本就会报 category，多报一条是噪音），用例同步注明原因

**文档**
